Overview

The problem

Most budgeting apps either overwhelm people with spreadsheet-like density or oversimplify to the point of being useless for anyone with more than one account. Users wanted a single view of spending, budgets, and investments that stayed readable without hiding the details that matter.

The solution

I designed and built a dashboard that groups transactions automatically, visualizes budgets against real spending in real time, and lets users drill into any category without leaving the page. Everything updates optimistically so the app feels instant even on slower connections.

My role

I owned the front end end to end — architecture, component design, state management, charting, and testing — while collaborating with a backend engineer on the API contract and a designer on the visual system.

Key Features

What Vault does well.

Real-Time Budgets

Budgets update the moment a transaction lands, with visual warnings before a category goes over.

Optimistic UI

Every action feels instant — the UI updates immediately and reconciles quietly with the server.

Custom Data Grid

A virtualized transaction table that stays smooth past 10,000 rows, with inline editing.

Secure by Default

Sensitive fields are encrypted client-side before transit, with session auto-lock after inactivity.

Fully Responsive

A distinct, touch-friendly mobile layout rather than a squeezed-down version of the desktop view.

Light & Dark Mode

A full dark theme built on the same design tokens, switchable instantly with no flash.

Challenges

Problems worth solving.

Early builds of the transaction table dropped frames past a few thousand rows. I rebuilt it as a virtualized grid that only renders visible rows, combined with memoized row components, which brought scroll performance back to a consistent 60fps regardless of dataset size.

Users often had the app open in multiple tabs, which caused budget totals to drift out of sync. I introduced a BroadcastChannel-based store sync so state updates in one tab propagate to every other open tab instantly.

Optimistic UI made the app feel fast, but failed requests occasionally left the UI out of sync with the server. I standardized rollback logic in RTK Query's cache lifecycle so every mutation cleanly reverts on failure.

Rather than inverting colors, I rebuilt the palette around semantic design tokens so light and dark mode share the same component code and switch instantly with no flash of unstyled content on load.
